# Archon Community Hub

Content packs add system design challenges and learning articles to Archon. A pack is plain Markdown and YAML, with no code. Users browse the hub from the **Hub** page and click **Baixar** to install a pack; its problems appear in the library and its articles in **Aprender**.

## Layout

```
hub/
  hub.yaml                         hub name
  packs/<pack-id>/
    pack.yaml                      manifest: id, name, version, description, author, license, tags
    problems/<problem-id>.md       frontmatter = problem fields, body = statement
    articles/<article-slug>.md     frontmatter = article fields, body = article
  templates/                       copy these to start
  dist/                            generated by `npm run hub:build`, read by the app
```

## Contributing a pack

1. Copy `templates/pack.yaml` to `packs/<your-pack-id>/pack.yaml` (the id must match the folder name).
2. Add problems from `templates/problem.md` and articles from `templates/article.md`.
3. Run `npm run hub:check` from the repository root. It validates every pack and points to the file and field that need fixing.
4. Run `npm run hub:build` to regenerate `dist/`, then try your pack in the app.
5. Open a pull request with the pack folder and the regenerated `dist/`.

When you change a published pack, bump its `version`. Installed users then see **Atualizar** on the Hub page.

### Writing a good problem

- **Every problem needs a grading key (`keyPoints`, 3–15 items).** The AI judges classify each point as covered, partial or missing, and 60% of each judge's score comes from it. Write each point as something you could check in a design: "Prevents double booking with conditional updates or row locks", not "Good consistency".
- Weight the points 1–5. Reserve 5 for what separates a passing answer from a failing one.
- `peakRps`, `latencyBudgetMs` and `expectedKinds` drive the Chaos Lab and the automatic pre-check, so keep them realistic for the stated scale.
- Ids are local to your pack. Inside the app they become `<pack-id>.<id>`, so they never collide with other packs. In `relatedArticles` and `relatedProblems` you can reference your own ids or built-in ones such as `caching` or `url-shortener`.

## Hosting a hub

The app reads `dist/index.json`. Locally it defaults to this folder. To share a hub, publish the repository and point the app's Hub page (pencil icon) or `HUB_INDEX_URL` to the raw URL, e.g. `https://raw.githubusercontent.com/<user>/<repo>/main/hub/dist/index.json`. Bundle paths in the index are relative, and every bundle is checked against its SHA-256 before installation.

Users can also install a single bundle (`dist/packs/<id>-<version>.json`) with **Importar pacote .json**, without a hub.
